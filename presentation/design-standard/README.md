## 기준의 층

1. **제품 디자인 시스템** — 값(색 · 글자 · 간격 · 모서리 · 선 · 모션 · 아이콘)과 컴포넌트, 내용 원칙. 시스템 파일은 [`../src/ds/`](../src/ds/)에 고치지 않고 둔다.
2. **덱 쪽 지침**(공통 덱 스킬 `references/design-standard.md` · `constitution.md`) — 시스템이 덱에 맡긴 두 가지(큰 글자 · 장 여백)만 여기서 고른다(presets.md:143).
3. **헌법**(designsystems.com Getting Started) — 시스템이 이미 그 안에 있다. 적용 기록은 [domain.md](domain.md).
4. **이 덱의 뼈대**([`../src/deck.css`](../src/deck.css) · [`../src/controls.css`](../src/controls.css)) — 시스템에 없는 덱 고유 모양만. 아래 「시스템 밖으로 둔 것」.
5. **공통 덱 스킬**(designing-decks-and-motion) — 구조 · 검사 계약(issues · 렌더 · 컨택트시트 · 표준 문서).

## 시스템 밖으로 둔 것(OP-14)

시스템 README는 「컴포넌트에 없는 모양을 토큰을 엮어 새로 만들지 않는다」고 한다. 덱은 앱 화면이 아니라서 아래 뼈대가 없으면 장이 서지 않는다. 그래서 **덱 고유 뼈대만** 정의하고 시스템 토큰과 시스템 컴포넌트의 선 · 모서리를 그대로 쓴다. 정본 OP-14 형식: 어긴 규칙 · 까닭 · 날짜 · 다시 나올 가능성(코드 자리에도 같은 주석).

2회차 「알려진 실패」를 고친 법(검사를 고치지 않고 덱을 고쳤다):

- `controls.css` `@page { size: 80rem 45rem }` 하드코딩 2건 → 쪽 크기를 CSS에서 빼고 머리 스크립트가 토큰 `layout-max-width`를 읽어 `@page`를 넣는다(값이 토큰 한 곳에만 있다).
- `shell.html` `--deck-k` 등 「없는 토큰」 6건 → 실행 값의 기본값은 `controls.css` `:root`에 있고, 머리 스크립트는 `d.style.setProperty("--deck-k", …)`로 직접 써서 검사기가 「정의」로 읽는다(전에는 도우미 함수 `set()`을 거쳐 「참조」로 읽혔다).
- 장 CSS(`src/slides/*.css`)는 여전히 덱 토큰(`--deck-*`)을 쓰지 않고 시스템 토큰을 쓴다(검사기가 장 CSS를 따로 읽는다).

예외 표시: `/* token-ok */`는 이제 쓰는 곳이 없다. `data-type-ok`(작은 글자 예외)도 쓰지 않는다 — 12px 미만은 어디서든 실패다.
